# scheMAGIC v0.2.0-rc.1

**Release date:** 2026-09-01

**Status:** pre-1.0 release candidate

This release consolidates the previously separate Component Library, Simulator/Editor, Measurement Workbench, and Motor/Power Designer work into one versioned application. The public static app exposes the Simulator at `/` and the Designer at `/designer`.

| Surface | Included capability | Trust boundary |
| --- | --- | --- |
| Simulator | Local ngspice-46 WASM analyses, living schematic, reviewed and imported models, namespaced user `.model`/`.subckt` libraries, and shareable browser persistence | Simulation is an engineering aid, not physical qualification |

| Designer | Deterministic Motor and Power requirements, candidate inspection, scenario artifacts, and structural exports | Current default candidates remain ineligible where hard evidence is unresolved |

| Sourcing | Provider-neutral request and policy contracts | Live provider access and production procurement authority remain disabled |

## Persisted-format compatibility

- Simulator V1 and legacy flat V2 documents migrate to the current Simulator V3 format.
- Designer multi-circuit documents use V4. V4 owns design blocks, circuits, scenarios, and a default circuit identifier.
- Parsers reject ambiguous or invalid shapes instead of interpreting incompatible contracts as the same version.
- Simulation outputs carry deterministic execution-receipt evidence plus Measurement run and scheduling provenance.

## Known limitations and tracked follow-up

- Strict Designer defaults still produce zero eligible Motor/Power candidates where hard evidence is unresolved; catalog and evidence deficits are tracked in [#10](https://github.com/hughminhphan/schemagic-sim/issues/10).
- `ti/LM311`, `ti/LM393`, and `ti/TLV3702` retain inherited recorded `supply_current.cir` native/WebAssembly comparison failures. `MCP6002` and `MCP6004` intentionally keep noise benches native-only.
- The repository does not yet freshly replay every electrical bench across all 771 packages in one bounded release command; [#14](https://github.com/hughminhphan/schemagic-sim/issues/14) tracks that gate.
- Manual assistive-technology review, authenticated external runtime attachments, external KiCad verification, and KiCad GUI open/save/reopen evidence remain external release evidence in [#12](https://github.com/hughminhphan/schemagic-sim/issues/12).
- Designer-to-Simulator handoff and portable simulation export remain incomplete in [#16](https://github.com/hughminhphan/schemagic-sim/issues/16).
- Live sourcing, full BOM/footprint authority, and physical implementation handoff remain bounded in [#11](https://github.com/hughminhphan/schemagic-sim/issues/11). Designer exports do not claim PCB layout, thermal proof, safety compliance, provider availability, or production release authority.
- GitHub Actions version modernization and `main` branch protection are tracked in [#15](https://github.com/hughminhphan/schemagic-sim/issues/15).
- The next model-library tranche starts from the 771-package baseline in [#18](https://github.com/hughminhphan/schemagic-sim/issues/18).
