# Robonyx Component Library design profiles

The internal `@opencircuit/design-library` compatibility module is the provider-neutral persisted engineering-profile boundary for Robonyx Designer. It owns exact-MPN profile, manufacturer-registry, admission-ledger, and catalog-release contracts. It does not contain offers, credentials, provider policy, live sourcing state, SPICE text, or model admission.

The package exports browser-safe canonical JSON/SHA-256 helpers, exact reversible profile paths, strict runtime parsers, one closed codec for each of the twelve V1 manifest classes, deterministic reviewed-only loading, and temporary synthetic staged adapters. `schema/profile.v1.schema.json` composes the closed envelope with exactly one class-facts schema for language-neutral consumers; every checked-in `$id` resolves under `https://schemas.schemagic.design/design-library/v1/` and is tested with AJV 2020.

Every admission entry carries the exact exported common check set plus one class-specific check. Declared statuses are compared with deterministic contextual results, so missing, extra, stale, and self-declared checks fail. Every present profile file must join back to its reserved ledger path/identity, while `authored`, `in_independent_review`, and `reviewed` states require a file. Catalog identity hashes only the manufacturer registry, reviewed admission projection, and canonical reviewed profile bytes sorted by exact path; planned work and release labels/timestamps cannot perturb it.

Draft 2020-12 schemas encode all closed structural rules, including fact-state/value/evidence conditions, vocabularies, numeric domains, and required operating-range conditions. Cross-value or cross-document comparisons that standard JSON Schema cannot express—minimum versus maximum, independent person identity, exact derived path/hash, and manufacturer-registry hostname joins—remain mandatory runtime/contextual checks.

The adapters preserve supplied staged evidence fields and explicit unknowns, always return `admissionState: "authored"`, and cannot pass reviewed admission. Missing provenance remains `null`; adapters do not invent URLs, hashes, timestamps, publication bases, measurements, or capacitor characteristics.

`ProfileUnit` extends the request schema's units only inside this package with `C` (coulomb), `J`, `K/W`, and `1/K`. A profile quantity using one of those units is not a design-request or constraint quantity and requires an explicit future conversion contract before crossing that boundary.

`docs/adr/0014-bound-typed-facts-v3-5.md` records the additive facts `3.5.0` contract for `power.power-inductor`, `shared.mlcc-capacitor`, and `power.integrated-synchronous-buck-regulator`. It is the first contract that can express a bound-typed field: a value the manufacturer publishes as a guaranteed production limit over recorded conditions, as distinct from a nominal, nameplate, typical, or point-characterization observation. It adds optional `inductanceMinimum` and `coreLossMaximum`; `effectiveCapacitanceMinimum` and `esrMaximum`; and `minimumOnTimeMaximum`, `minimumOffTimeMaximum`, and `thermalResistanceJunctionAmbient` with its required `jedec_2s2p` or `declared` board qualifier. A bound-typed fact is either reviewed against published guaranteed evidence or unknown, must carry the conditions it is bounded over, and may not contradict the observation it bounds. Migration is additive only and never automatic: catalog release `2026-08-27.2` keeps all 24 profiles on their existing `2.0.0` through `3.4.0` contracts with unchanged bytes, every predecessor validator still rejects the `3.5.0` keys as unknown, and `3.5.0` admits no profile by itself. The Power passive kernel consumes a present bound-typed field as a condition-covering bound and is byte-for-byte unchanged when the field is absent.
